# BIG IDLE HEROES

월드 오브 워크래프트: 포에버(WoW Forever)용 애드온입니다. 화면 한켠의 **전투 창**에서 영웅 파티가 저절로 싸우고, 플레이어는 틈틈이 장비·특성·룬을 관리하는 **방치형 파티 RPG 미니게임**입니다.

- 파티는 최대 **5명 (탱커 1 · 딜러 3 · 힐러 1)**
- 처음에 **얼라이언스 / 호드**를 고르면, 영웅이 진영별로 직업마다 정해진 **종족**의 모습이 됩니다
- **오리지널 9개 직업, 28개 전문화** 중에서 골라 영웅을 만들고, 종족은 직업과 진영으로 정해지고(오리지널 종족) 성별은 접속한 내 캐릭터의 성별을 따르며, 종족·성별에 맞는 **"이름 성" 형식의 무작위 이름**이 붙습니다 (최대 12명 보유)
- **특성**(능력치, 레벨마다 1점)과 **기술**(4레벨마다 1점, 레벨에 따라 열림)이 따로입니다
- 120개 스테이지가 **오리지널 와우의 지역·던전·공격대를 권장 레벨 순서대로 도는 길**입니다: 엘윈 숲 → 던 모로 → … → 죽음의 폐광 → … → 화산 심장부 → 검은날개 둥지 → 안퀴라즈 사원 → **낙스라마스**
- 모바일 MMORPG 스타일 화면(940×690): 위 머리줄(진영·지역·파티 전투력·재화), 하단 메뉴 6개(영웅·장비·편성·룬·스테이지·동료), 빨간 점 알림, "추천" 안내, 보스 체력바
- 전투 창은 **오른쪽 아래 모서리를 끌어 크기 조절**(비율 유지)
- 전투 창의 영웅·몬스터·우두머리·소환물·동료는 **게임에 들어 있는 3D 모델**로 움직입니다(대기·걷기·공격·시전·피격·사망, 드루이드 변신). 아래 "3D 모델" 참고
- 8등급 장비, 상자, 용광로 기능(융합·제작·보석·마법부여·각인·분해·추출·행운의 인장 — 모두 장비 화면 안), 룬 트리, 동료, 오프라인 보상
- 한국어 전용 (영어 등 다른 언어 클라이언트에서도 한글 글꼴로 표시)

## 설치

1. 이 저장소의 `BigIdleHeroes` 폴더(또는 받은 `BigIdleHeroes-v….zip`을 푼 `BigIdleHeroes` 폴더)를 통째로 와우 포에버의 `Interface/AddOns/` 아래에 복사합니다.
   (결과: `Interface/AddOns/BigIdleHeroes/BigIdleHeroes.toc`, 그 옆에 `Media/` 폴더)
2. 게임을 실행하고 캐릭터 선택 화면의 **애드온** 목록에서 `BIG IDLE HEROES`을 켭니다.
3. 접속하면 **진영 선택** 창이 바로 열립니다(첫 영웅을 만들기 전에는 전투 창이 뜨지 않습니다). 얼라이언스나 호드를 고르면 영웅 화면에서 **영웅 만들기** 창이 이어서 열립니다. 직업 → 전문화 → 이름을 정하면 첫 영웅이 무료로 만들어지고 전투가 시작됩니다.
4. 메뉴는 `/bih`로 열고 닫습니다 (`/bih bar` 전투 창 표시/숨김, `/bih reset` 전투 창 위치 초기화). 채팅창에 나오는 이 애드온의 알림은 앞에 `[B.I.H]`가 붙습니다.
5. `/bih model`(또는 `/bih 모델`)은 **3D 모델 확인 창**입니다. 게임에 들어 있는 3D 모델 다섯 개(고른 영웅의 모습, 내 캐릭터, 첫 스테이지의 몬스터, 우두머리 라그나로스, 소환물 임프)를 띄우고, 동작(서기·걷기·달리기·공격·시전·피격·죽음, 또는 번호), 방향, 카메라 거리를 바꿔 볼 수 있습니다. 모델마다 아래에 쓴 모델 기능이 이 클라이언트에서 되는지(됨·없음·오류)와 불러온 모델 파일 번호가 나옵니다. 전투 창을 그림 대신 3D 모델로 바꾸기 전에 어떤 기능을 쓸 수 있는지 확인하는 창입니다. [전투 모습]은 파티 영웅·지금 스테이지의 몬스터와 우두머리·라그나로스를 전투 창과 같은 방식(크기를 잰 장면 모델)으로 한 땅선 위에 나란히 세워, 크기와 발 위치를 비교합니다. 모델마다 잰 키·길이와, 게임의 투영으로 잰 카메라 거리 보정 값도 나옵니다. 장면 모델은 게임의 투영(Project3DPointTo2D)으로 발과 머리가 실제로 그려진 곳을 재서, 발이 땅선에 오고 키가 맞도록 모델마다 크기와 위치를 스스로 고칩니다(투영의 단위와 원점은 정사각형 틀의 가운데로 알아냅니다). 모델 아래에 고친 크기와 발 위치가 나옵니다. [옷 입히기]는 직업의 던전 세트를 그 종족의 맨몸에 입혀 봅니다: 내 캐릭터의 몸을 그 종족으로 바꾸고 아무것도 입히지 않은 몸(SetModelByUnit의 종족 지정, 내 캐릭터의 성별), 같은 몸에 세트를 입힌 모습(영웅이 그려지는 모습), 그리고 비교용으로 모델 틀에서 내 캐릭터에 세트를 입힌 모습. [<] [>]로 직업·진영 18가지를 바꿉니다. [효과]는 주문 효과를 세 가지 방법으로 나란히 재생합니다: 전투 창과 같은 장면 모델에 주문 효과 키트(SetSpellVisualKit), 모델 틀에 같은 키트(ApplySpellVisualKit), 효과 모델 파일(손 효과·투사체·적중 효과)을 직접 띄우기. 번개 화살·화염구·얼음 화살·어둠의 화살·천벌·신비한 사격·성스러운 일격·치유·치유의 물결 중 하나를 고르면 시전 → 발사 → 투사체 비행 → 적중을 되풀이하고, 방법마다 이 클라이언트에서 되는지(됨·없음·오류)와 파일을 불러왔는지가 나옵니다. 키트 번호와 효과 파일 번호는 `Data/Effects.lua`에 있습니다(오리지널 1.12 클라이언트의 주문 효과 표). 몬스터 401종·우두머리 120명·소환물·동료에 쓸 NPC 번호는 `Data/Models.lua`에 있습니다(번호마다 wowhead의 이름으로 확인). 모델이 안 보이면 [다시 불러오기]를 누르세요(처음 보는 몬스터는 정보를 받아 오는 데 잠깐 걸립니다).

`BigIdleHeroes.toc`의 `## Interface:` 값은 포에버 베타 기준인 **16001**입니다. "구버전 애드온"으로 표시되면 애드온 목록에서 *구버전 애드온 사용*을 켜거나, 게임에서 `/dump select(4, GetBuildInfo())`로 확인한 숫자로 바꾸면 됩니다.

**예전 이름(BIG W.O.W IDLE — 폴더 `BigWowIdle`, 그 전 BIG W.O.W HEROES — `BigWowHeroes`, Big Idle W.O.W Heroes — `BigIdleWoWHeroes`)에서 옮겨 오기:** 애드온 폴더 이름이 바뀌어 와우가 다른 저장 파일을 찾습니다. 진행 상황을 이어 가려면
1. 게임을 완전히 끕니다.
2. `Interface/AddOns/BigWowIdle`(또는 더 예전 폴더)를 지우고 새 `BigIdleHeroes` 폴더를 넣습니다(둘 다 켜 두지 마세요).
3. `WTF/Account/(계정 이름)/SavedVariables/BigWowIdle.lua`(또는 `BigWowHeroes.lua`, `BigIdleWoWHeroes.lua`)를 같은 곳에 `BigIdleHeroes.lua`라는 이름으로 복사합니다.
4. 게임을 켜면 예전 저장 데이터를 그대로 불러옵니다(저장 변수 이름은 그대로라 내용이 그대로 옮겨집니다).

예전 버전의 저장 데이터는 자동으로 옮겨집니다.
- 1.x: 직업별 영웅은 같은 역할의 전문화 영웅이 되고(레벨·장비·진행도 유지), 특성 점수는 돌려받습니다.
- 2.0: 특성 트리에 있던 기술은 새 기술 점수로 옮겨지고(새 한도를 넘는 단계만 돌려받음), 영웅마다 성별과 성(姓)이 붙습니다. 처음 접속할 때 진영을 고릅니다.

## 화면 구성

**전투 창 (HUD)** — 그 지역의 실제 게임 풍경 그림을 깔고, 그 앞에 지역의 나무·덤불·바위를 게임의 3D 모델로 세운 배경 위에서 파티가 싸웁니다(파티가 다음 무리로 걸어갈 때 모델이 지나갑니다). 왼쪽 드래그로 옮기고, 오른쪽 아래 모서리로 크기를 바꾸고(우클릭하면 원래 크기), 우클릭으로 메뉴를 엽니다.
- 위: 난이도·지역 이름, 웨이브 진행 점(마지막은 해골 = 우두머리), 골드. 우두머리가 나오면 웨이브 점 자리에 큰 체력바가 나와 전투 글자나 "전멸..."과 겹치지 않습니다
- 아래: **추천**(누르면 바로 하거나 해당 화면을 엽니다), 자동 진행 버튼, 상자 3종, 메뉴 바로가기(빨간 점 = 할 수 있는 일이 있음)

**메뉴 창** — 위 머리줄에 게임 이름·진영, 지금 싸우는 곳과 **파티 전투력**, 골드와 재료 5종(누르면 장비 > 재료의 그 탭), 설정(톱니바퀴)·닫기가 있고, 아래 메뉴 6개(영웅 · 장비 · 편성 · 룬 · 스테이지 · 동료)로 화면을 옮깁니다. 알림 메시지는 메뉴 창 위쪽 테두리(메뉴 창이 닫혀 있으면 전투 창 위)에 나타나 버튼을 가리지 않습니다.

모든 화면은 같은 틀을 씁니다: **왼쪽에서 고르고, 오른쪽 위 알약 모양 탭으로 볼 것을 바꾸고, 버튼은 그 버튼이 바꾸는 것 바로 옆에** 있습니다 (`UI/Layout.lua`).

- 목록의 줄마다 그 줄의 버튼이 붙어 있습니다(재료 줄의 [1회] [모두] [모두 분해], 진형 칸의 [<] [빼기] [>]).
- 목록 전체에 대한 버튼은 그 목록의 머리줄 오른쪽에 있습니다(특성 → [자동 배분] [초기화], 가방 → [정리], 진형 → [자동 편성]).
- 색이 뜻하는 것은 어디서나 같습니다: 금색 = 주된 행동, 파란색 = 여럿에 한꺼번에 하는 행동(자동 편성, 상자 열기, 1회 융합 …), 어두운색 = 보조, 빨간색 = 잃는 것(분해, 초기화, 떠나보내기, 추출, 전체 해제).
- **잃는 행동은 확인 창이 한 번 더 묻습니다** ("철제 둔기을(를) 분해하시겠습니까?" → 취소 / 분해). 가방에서 우클릭으로 분해할 때도 같습니다.
- 여러 값 중 하나를 고르는 버튼(가방 보기, 분해 등급)은 누르면 **목록이 펼쳐지고**, 지금 값에 체크 표시가 있습니다.
- 장비의 **홈은 그림으로** 보입니다: 보석(하늘색 테두리), 마법부여(보라색), 룬 각인(금색) 순서로, 박힌 홈은 그 안에 넣은 재료의 아이콘과 붙은 능력치, 빈 홈은 빈 원으로 종류마다 한 줄씩 나옵니다(설명 창, 보석·마법부여·각인 탭).
- 장비의 초록색 능력치(등급마다 붙는 무작위 능력치)와 보석·마법부여·각인으로 붙는 능력치는 **무작위**입니다(종류도, 값도). 장비 설명에는 그 능력치가 그 장비의 부위·레벨·등급에서 나올 수 있었던 최소~최대값을 `+8.4% 재사용 대기시간 감소 (4.2~8.4)`처럼 함께 적습니다. 흰색 기본 능력치는 레벨과 등급으로 정해지는 고정값이라 범위가 없습니다.
- 누를 수 없는 금색 버튼 근처에는 그 이유가 빨간 글씨로 나옵니다(골드 부족, 가방 가득 참 …).
- 글자는 10 이상, 한 줄 글자는 칸 안에 들어가게 했습니다. `python3 tests/run.py layout`이 화면 78가지 상태(확인 창, 펼친 목록, 우두머리 전투·전멸, 작은 전투 창, 오프라인 보상, 첫 영웅 만들기, 잠긴 기능 포함)를 모두 그려 보고 글자 잘림·넘침·줄바꿈, 글자끼리·글자와 버튼 겹침, **글자와 옆 그림·버튼이 6픽셀보다 가까움**, **패널·카드·버튼 테두리끼리 겹치거나 닿음**, 알림 점이 이웃을 건드리거나 숫자가 점 밖으로 나감, 가려짐, 창 밖, 같은 버튼 중복, 작은 글씨를 검사합니다.

## 밸런스

`tests/`의 도구로 맞췄습니다.

- **전문화 밸런스** (`python3 tests/run.py bench`): 같은 동료·레벨·장비로 각 전문화를 넣어 비교합니다. 딜러는 죽지 않는 목표(단일 대상 + 3마리 무리)에 대한 파티 총 피해로, 탱커·힐러는 실제 피해를 받는 어려운 스테이지에서 측정하고, 전문화별 보정값(`Data/Classes.lua`의 `ns.SPEC_TUNE`)을 조정합니다. 결과: 같은 역할 안에서 모든 전문화가 중앙값의 약 ±2% 안에 있습니다(보정 전 최대 10% 차이).
- **전투력** (영웅·장비·편성 화면과 머리줄의 파티 전투력): 역할과 전문화에 상관없이 같은 기준입니다. `√(공격 × 유효 생명력) × 기술 속도 × 치유 효과`이고, 공격 = 공격력 × 치명타 기대값 × (1 + 그 계열·모든 피해%) × (1 + 연속 타격/2) × 장비·버프로 오른 공격 속도, 유효 생명력 = 생명력 ÷ 받는 피해 비율(방어도·피해 감소·회피·막기), 기술 속도 = (1 + 시전 속도/2) ÷ (1 − 재사용 감소/2), 치유 효과 = 1 + 치유량/2입니다. 전문화마다 다른 기본 공격 속도와 보정값(`SPEC_TUNE`)은 빼고 계산하므로 같은 레벨·같은 등급 장비면 탱커·딜러·힐러가 비슷하게 나옵니다(Lv 40의 모든 전문화가 서로 17% 안쪽). 아이템 툴팁의 "○○ 기준 장비 점수 +n%"는 따로, 그 영웅의 역할(탱커는 생존, 딜러는 피해, 힐러는 치유)에 무게를 둔 점수로 자동 장착이 쓰는 값입니다.
- **전투 연산 검사** (`python3 tests/run.py audit`): 능력치를 고정한 영웅과 가짜 몬스터로 실제 전투를 돌려, 기록된 피해·치유·시전이 공식·능력치 화면·기술 설명과 맞는지 49가지를 잽니다(공격 속도, 치명타, 연속 타격, 계열 피해, 흡수·적중 시 회복, 회피·막기·방어도·저항·피해 감소·흡수·가시, 재사용 대기시간과 시전 속도, 기술 160개 전부의 설명 수치, 몬스터 상태이상·우두머리 기술, 처치 골드·경험치, 전문화 28개 실전 불변식).
- **장비 레벨**: 장비의 요구 레벨은 장비 레벨 − 2입니다. 상자(와 행운의 인장)에서 나오는 장비는 스테이지 레벨을 따르되, 파티에서 레벨이 가장 높은 영웅이 낄 수 있는 데까지(그 영웅 레벨 + 2)만 나옵니다(`Loot.GearLevel`). 그래서 나오는 장비는 거의 다 바로 낄 수 있습니다(시뮬레이션 48시간 분량, 레벨 17 이후 상자 장비 99%). 스테이지 화면의 보상 칸에 지금 받을 장비 레벨과 착용 레벨이 나옵니다.
- **몬스터 강화**: 파티가 늘 최신 장비를 끼는 만큼, 레벨 25를 넘는 몬스터의 생명력과 공격력은 레벨마다 약 3.5%씩 더 오릅니다(`Data/Stages.lua`의 `ns.MIGHT`).
- **진행 속도** (`python3 tests/run.py balance 220`): 봇이 쉬지 않고 최적에 가깝게 관리할 때 일반 완료 약 5시간, 영웅 약 26시간, 신화 약 101시간, 220시간 시점에 신화+ 24/30 스테이지(영웅 Lv 88). 스테이지를 오리지널 지역·던전·공격대로 바꾼 뒤에도 바꾸기 전과 막마다 몇 % 안에서 같습니다(몬스터·우두머리 수치가 같은 자리의 것과 똑같기 때문). 동료를 얻는 처치 수(`Data/Pets.lua`)는 몬스터 종류가 바뀐 만큼 다시 맞췄습니다(시뮬레이션 세 번에서 같은 시점에 얻도록): 고양이 약 131시간, 닭 약 10시간, 해골 약 58시간은 예전과 같고, 정령 약 22시간, 임프 약 18시간, 새끼용 약 14시간, 다람쥐 약 15시간은 그 종류의 몬스터가 한꺼번에 나오는 곳에 맞춰 예전보다 5~20시간 일찍 얻습니다. 각 막의 공격대 우두머리가 넘기 어려운 벽 역할을 하되 며칠씩 막히지 않도록 조정했습니다. 몬스터 경험치는 `Data/Stages.lua`의 `ns.EXP_RATE`(1.2)로 한꺼번에 조절합니다.

## 3D 모델 (전투 창)

전투 창의 영웅·몬스터·우두머리·소환물·동료는 게임에 들어 있는 3D 모델로 그립니다(설정 > 화면 > "영웅·몬스터를 게임의 3D 모델로 보기", 기본 켜짐). 근접 공격 소환수(사냥꾼의 야수, 지옥사냥개)는 걸어갈 때는 소환한 영웅 옆에 있다가, 싸움이 시작되면 근접 영웅들이 있는 맨 앞까지 걸어 나가 몬스터에 붙어 싸웁니다. 원거리 공격 소환수는 늘 소환한 영웅 옆에, 동료는 파티 맨 뒤에 섭니다.

- **영웅**: 내 캐릭터의 몸을 그 직업의 종족으로 바꾸고(아무것도 입히지 않은 몸, SetModelByUnit의 종족 지정) 그 직업의 방어구를 입히고 전문화의 무기를 손에 든 모습입니다. 입는 장비는 계정 진행(끝까지 깬 난이도 수, `ns.GearTier`)에 따라 바뀌며 모든 영웅(새로 만든 영웅 포함)이 같은 단계를 입습니다(`Data/Models.lua`의 `ns.MODEL.armorTier`·`weaponTier`):

  - 일반 30 클리어: 20레벨대에 입을 수 있는 가장 좋은 장비와 무기. 가죽 착용자는 세트(도적·사냥꾼: 데피아즈 가죽, 드루이드·주술사: 독사의 포옹), 40레벨 전이므로 전사·성기사는 사슬, 사냥꾼·주술사는 가죽
  - 영웅 30 클리어: 1단계 던전 세트(전사: 용맹의 전투장비 등)와 오리지널 60레벨 5인 던전의 가장 좋은 무기(분노 전사·무법 도적은 달렌드의 성검·부족 수호검, 사냥꾼은 고대의 해골 장궁·검은까마귀 등)

- **스테이지 탭 그림**: 세계 카드와 스테이지 상세의 지역 그림은 게임에 들어 있는 그 곳의 로딩 화면입니다(`Data/LoadingScreens.lua`). 야외 지역은 Forever의 대륙 로딩 화면(동부 왕국·칼림도어)이고, 던 모로는 옛 아이언포지, 저습지는 발굴지, 티리스팔 숲은 로데론 폐허의 Forever 로딩 화면입니다. 던전·공격대는 오리지널 로딩 화면(오닉시아의 둥지는 오리지널 공격대 로딩 화면)입니다. 클라이언트에 Forever 파일이 없으면 오리지널 대륙 로딩 화면을 씁니다. 칸 모양에 맞게 그림 가운데 띠를 잘라 보여 주고, 로고와 테두리는 보이지 않게 합니다. 세계 카드는 모험의 시작 = 동부 왕국, 넓어지는 세계 = 칼림도어, 깨어나는 위협 = 줄구룹, 최후의 결전 = 낙스라마스입니다.
- **움직이는 배경**: 맨 뒤 풍경 그림은 그림과 그 좌우를 뒤집은 그림을 번갈아 끝없이 이어 붙여, 파티가 걸을 때 천천히 흘러갑니다. 발밑에는 그 지역의 실제 땅 텍스처(엘윈 숲 풀밭, 듀로타 붉은 흙, 던 모로 눈, 던전은 그 던전의 바닥 돌·타일 등, `Data/Scenery.lua`의 `ns.GROUND`)를 깔아 걷는 속도로 흘러가게 하고, 윗부분은 풍경 그림 쪽으로 옅어집니다. 파티가 다음 무리로 걸어갈 때만 배경이 움직이고(속도는 부드럽게 붙었다 줄어듦), 싸우는 동안에는 모두 멈춰 있습니다.
- **전투 배경 그림**: 스테이지마다 그 곳의 게임 화면 스크린샷을 전투 창 모양의 띠로 잘라 만든 그림(`Media/Scenes/`, 59장, 512×128 TGA)을 맨 뒤에 깝니다. 던전·공격대는 그 안쪽 모습입니다. 출처는 `docs/BACKDROP_SOURCES.md`에 있습니다.
- **지역 배경**: 야외 스테이지는 싸움 뒤에 그 지역의 나무·덤불·바위·풀 모델(게임 클라이언트의 `world/` 폴더에서 지역마다 손으로 고른 것, 묘비·울타리·건물·소품은 뺌)을 세 줄로 세웁니다. 먼 줄은 그 지역의 큰 나무(멀리 있는 것처럼 반투명하고 색이 빠지고 공기 색이 섞임), 가운데 줄은 작은 나무와 바위, 가까운 줄은 덤불·풀·그루터기입니다. 모델마다 실제 키를 따라 줄의 크기 범위 안에서 크기가 정해지고, 너무 작거나 크거나 옆으로 긴 모델(벽·절벽)은 다른 것으로 바뀝니다. 줄끼리 겹치지 않게 엇갈려 놓입니다. 영웅·몬스터는 늘 배경 모델 앞에 그려집니다(모델 창마다 자기 영역의 깊이를 따로 지움, `SetAllowOverlappedModels`). 던전·공격대 안쪽은 나무·바위 대신 그 던전에 실제로 있는 소품을 세웁니다(스칼로맨스: 책장·촛대·가마솥·표본 병, 울다만: 티탄 석상·화로·책상·항아리, 검은바위 나락: 타우릿산 석상·화로·모루·작업대, 검은날개 둥지: 피 실험 기계·둥지·용 알, 낙스라마스: 테슬라 코일·수술대·켈투자드의 왕좌 등). 붉은십자군 수도원은 도서관·무기고·대성당, 스트라솔름은 광장·도살장마다 소품이 다릅니다. 통곡의 동굴에는 랩터 둥지와 알, 오닉시아의 둥지에는 용 알과 둥지가 더해집니다. 안쪽 소품은 사람 크기에 맞춘 작은 줄 크기로 그립니다. 파티가 다음 무리로 걸어가는 동안 가까운 줄은 걷는 속도로, 먼 줄일수록 느리게 지나갑니다. 지역마다 쓰는 모델과 파일 번호는 `Data/Scenery.lua`에 있습니다. 설정 > 화면 > "전투 창 뒤에 지역의 나무·바위 모델 보기"로 끌 수 있습니다.
- 몬스터 401종·우두머리 120명·동료: `Data/Models.lua`의 NPC 번호. 몬스터와 우두머리는 모두 오리지널 지역·던전·공격대의 NPC이고, 모델 번호는 전부 오리지널 데이터베이스(CMaNGOS classic-db)의 값입니다.
- 모델은 **모델 번호(표시 번호)로 불러 옵니다.** 게임 데이터에서 바로 읽으므로 서버에 NPC를 물어보지 않습니다. 모델이 들어올 때까지는 아이콘이 보이고, 끝내 안 되면 아이콘으로 둡니다.
- **모델마다 크기를 잽니다.** 전투 창의 모델 하나하나는 카메라가 하나 달린 작은 장면(ModelScene)이고, 카메라는 모두 똑같습니다. 모델이 들어오면 모델의 크기 상자(GetActiveBoundingBox)를 재서, 키를 그 칸의 높이(영웅 74 × 종족 비율, 몬스터 70, 우두머리 98)에 맞추고, 발(상자 바닥)을 땅선에, 가운데를 칸 가운데에 둡니다. 그래서 모델 원래 크기와 상관없이 모두 같은 땅선에 서고(라그나로스도 우두머리 크기로 보임), 전투 창을 키우고 줄이면 창과 정확히 같은 비율로 커지고 작아집니다. ModelScene이 없는 클라이언트는 예전처럼 PlayerModel로 그립니다(창 크기가 바뀌면 카메라를 다시 맞춤).
- **이 게임이 보여 준 모델을 기억합니다**(저장 파일 `db.models`): NPC마다 실제로 나온 모델 번호, 그리고 이 게임에 없는 모델 번호. 다음부터는 처음부터 맞는 번호로 바로 불러 오고, 없는 번호를 기다리지 않습니다.
- 모델 칸은 모델 키의 3배인 정사각형이라 날개·꼬리·큰 무기가 잘리지 않습니다. 긴 모델(용·늑대)은 길이의 0.6배를 키로 보고 맞춰 칸 안에 들어옵니다.
- 전투는 0.1초마다 계산되지만, 전투 창은 그 사이를 매 프레임 이어 그려 영웅과 몬스터가 끊기지 않고 부드럽게 걸어갑니다. 걷기 동작도 걸음 사이에 끊기지 않고, 멈춰 서 있으면 걷지 않습니다(공격 사이에도 서기 동작).
- 쓰러진 영웅·몬스터는 죽는 동작을 한 번 하고 쓰러진 채로 있습니다.
- 영웅은 오른쪽(몬스터 쪽), 몬스터는 왼쪽을 봅니다. 동작: 서기 0, 걷기 4, 공격 17, 시전 53, 피격 9, 죽음 1 → 쓰러짐 6. 설정에서 끄면 아이콘으로 보입니다.

## 설계에 대해

*Task Bar Hero* 류의 "작업 표시줄 방치형 RPG"가 가진 **시스템 구성**(자동 전투, 특성 트리, 등급별 홈이 있는 장비, 9개 융합, 큐브형 제작대, 룬 트리, 동료, 오프라인 보상)을 참고해 같은 장르로 만들었습니다. 이름·지역·몬스터는 워크래프트 테마이고, 아이템/기술/룬 목록, 확률표, 수치는 이 애드온용으로 새로 설계했습니다.

**그림:** `BigIdleHeroes/Media/`의 UI 이미지(패널, 버튼, 슬롯, 링, 역할 아이콘, 지역 배경 등 30종)는 모두 `tools/make_art.py`가 직접 그려 만든 것입니다. 아이템·기술·직업 아이콘은 게임 클라이언트에 이미 들어 있는 아이콘 경로만 참조합니다(파일을 포함하지 않음).

Task Bar Hero 및 그 개발사, Blizzard Entertainment와는 아무 관련이 없는 팬 제작물입니다.

## 테스트와 도구

게임 없이 로직과 화면을 검증할 수 있도록 WoW UI API를 흉내 낸 모의 환경과 자동 플레이 봇이 있습니다.

```bash
pip install lupa pillow numpy
```

```bash
python3 tests/run.py
```

| 명령 | 하는 일 |
| --- | --- |
| `python3 tests/run.py systems` | 데이터 무결성(전문화, 120개 지역, 기술), 파티 역할, 영웅 생성·이름, 능력치, 아이템, 용광로, 전투, 저장 데이터 이전 |
| `python3 tests/run.py ui` | 실제 로딩 순서대로 띄운 뒤 모든 화면의 흐름(영웅 만들기, 진형 바꾸기, 특성, 기술, 장비·가방, 재료, 융합·제작·보석·추출, 룬, 스테이지, 동료, 전투 창, 확인 창, 선택 목록)을 눌러 보고, 버튼을 수천 번 무작위로 누릅니다 (한국어 클라이언트와 그 밖의 클라이언트) |
| `python3 tests/run.py layout` | 화면 78가지 상태(빈 저장, 잠김, 가득 참, 가장 긴 이름 등)를 브라우저로 그려 글자 잘림·넘침·줄바꿈, 겹침, 가려짐, 창 밖, 같은 버튼 중복, 10보다 작은 글씨를 검사 (`tests/layout_check.js`) |
| `python3 tests/run.py balance 330` | 봇이 330시간 분량을 플레이하며 진행 속도를 출력 |
| `python3 tests/run.py audit` | 전투 연산 검사: 능력치를 고정한 실제 전투로 공식·능력치 화면·기술 설명 49가지를 측정 (`tests/combat_audit.lua`, `tests/combat_lab.lua`) |
| `python3 tests/run.py bench` | 전문화 밸런스 측정·조정 |
| `python3 tests/run.py cover` | 테스트가 실행한 코드 줄 비율 |
| `python3 tools/make_art.py` | 기본 UI 이미지 다시 만들기 |
| `python3 tests/preview.py` | 화면 배치 미리보기 `tests/out/preview_koKR.html` (실제 UI 이미지 사용, 게임 아이콘은 대체 그림) |

**주의:** 위 검증은 모두 모의 API에서 한 것이며, 이 코드는 실제 와우 포에버 클라이언트에서 실행해 본 적이 없습니다. 실제 클라이언트에서 Lua 오류가 나면 오류 메시지(`/console scriptErrors 1`)와 함께 알려 주세요. 아이콘이 클라이언트에 없으면 그 칸만 비어 보일 수 있습니다.

## 폴더 구조

```
BigIdleHeroes/              애드온 본체 (이 폴더를 AddOns에 복사)
  Core/                  공용 유틸리티, 글꼴, 이벤트
  Data/                  직업·전문화, 진영·종족, 기술, 이름, 몬스터, 지역, 아이템, 룬, 동료, 3D 모델 NPC 번호(Models.lua), 지역 배경 모델(Scenery.lua), 로딩 화면(LoadingScreens.lua)
  Systems/               저장, 능력치, 아이템, 영웅, 상자, 용광로, 전투, 오프라인, 목표 안내
  UI/                    위젯, 화면 공통 틀(Layout.lua), 3D 모델(Figure3D.lua), 전투 창, 모델 확인 창, 메뉴 창과 각 화면
  Media/                 기본 UI 이미지 (TGA)
docs/UI_RESEARCH.md      모바일 게임 화면 조사 기록
tests/                   모의 WoW API, 봇, 테스트, 벤치마크, 미리보기
tools/make_art.py        기본 UI 이미지 생성기
```

진행 상황은 계정 공용 SavedVariables(`BigWowIdleDB`, 파일 `SavedVariables/BigIdleHeroes.lua`)에 저장됩니다.
